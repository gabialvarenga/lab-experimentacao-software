**Contexto e justificativa**

O Lab04 pede código que roda do início ao fim com um único comando e semente fixa. Toda a sprint depende da estrutura de pastas e do CI existirem no `main`.

**Objetivo**

Criar o esqueleto de `lab04/` (pacote `lab04`, `tests/`, `dados/`, `docs/`), `requirements.txt`, `pytest.ini`, README com o comando único e o workflow `lab04-testes.yml`.

**Definições adotadas**

- Semente global: `numpy.random.default_rng(42)`, lida de `config.yaml`.
- Dependências: NumPy, SciPy, pandas, Plotly, PyYAML, requests, pytest, pytest-cov.
- O CI roda `pytest` a cada push e PR, com `working-directory: lab04`.

**Interface congelada**

- Pacote `lab04` importável; `python -m lab04 --help` funciona.
- Módulos previstos (arquivos vazios ou com docstring): `coleta`, `descritiva`, `calibracao`, `gerador`, `testes`, `simulacao`, `graficos`, `dashboard`.

**Procedimento**

1. Criar as pastas conforme a seção 5 do planejamento.
2. Escrever `requirements.txt`, `pytest.ini` e `config.yaml` (só `semente: 42` por enquanto).
3. Escrever um teste mínimo que passa (ex.: importa o pacote), para o CI não nascer vermelho.
4. Criar `.github/workflows/lab04-testes.yml` nos moldes do `lab03-testes.yml`.
5. Escrever o README com integrantes, link do Kanban, estrutura e o comando único (ainda esqueleto).
6. Atualizar a tabela de laboratórios do README da raiz.

**Saída esperada**

PR mesclado na `main` com a estrutura, o CI verde e o README.

**Casos de borda**

- Python 3.12 e dependências instalam em ambiente limpo.
- O CI não pode depender de segredos (o token só é usado na coleta, fora do CI).

**Critérios de aceite**

- [ ] `pip install -r lab04/requirements.txt` funciona.
- [ ] `pytest` passa localmente e no CI.
- [ ] `python -m lab04 --help` roda.
- [ ] README com o comando único descrito.

**Fora do escopo**

Implementar coleta, testes, gerador e gráficos (demais Issues da sprint).

**Dependências**

Nenhuma. Bloqueia todas as outras Issues de código.
