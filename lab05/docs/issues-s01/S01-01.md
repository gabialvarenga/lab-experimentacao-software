**Contexto e justificativa**

Todas as Issues de código da sprint dependem da estrutura de pastas e do CI existirem no `main`. O Lab05 reaproveita código do Lab04 (testes de hipótese e motor de simulação), então a estrutura precisa deixar isso explícito.

**Objetivo**

Criar o esqueleto de `lab05/` (pacote `lab05`, `tests/`, `dados/`, `docs/`), `requirements.txt`, `pytest.ini`, `config.yaml` com a semente, README e o workflow `lab05-testes.yml`.

**Definições adotadas**

- Python 3.12; dependências: NumPy, SciPy, pandas, Plotly, Streamlit, PyYAML, pytest, pytest-cov.
- Semente global em `config.yaml` (`semente: 42`).
- Código reaproveitado do Lab04 é copiado para `lab05/lab05/` com a origem citada no docstring (o Lab05 não importa de `lab04/`, para cada lab rodar sozinho).
- O CI roda `pytest` a cada push e PR, com `working-directory: lab05`, sem Docker (os testes do executor usam saídas gravadas do cliente de carga).

**Interface congelada**

- Pacote `lab05` importável; `python -m lab05 --help` funciona.
- Módulos previstos (vazios ou com docstring): `ambiente`, `executor`, `validacao`, `descritiva`, `testes`, `poder`, `graficos`, `app`.

**Procedimento**

1. Criar as pastas e os arquivos de configuração.
2. Escrever um teste mínimo que passa, para o CI não nascer vermelho.
3. Criar `.github/workflows/lab05-testes.yml` nos moldes do `lab04-testes.yml`.
4. Escrever o README com integrantes, link do Kanban, estrutura e o comando único (esqueleto).
5. Atualizar a tabela de laboratórios do README da raiz (está desatualizada desde o Lab02).

**Saída esperada**

PR mesclado na `main` com a estrutura, o CI verde e o README.

**Casos de borda**

- Dependências instalam em ambiente limpo com Python 3.12.
- O CI não depende de Docker nem de segredos.

**Critérios de aceite**

- [ ] `pip install -r lab05/requirements.txt` funciona.
- [ ] `pytest` passa localmente e no CI.
- [ ] `python -m lab05 --help` roda.
- [ ] README da raiz e do `lab05/` atualizados.
