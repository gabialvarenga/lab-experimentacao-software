**Contexto e justificativa**

O documento pode ser um dashboard (seção 8), e o professor precisa conseguir abri-lo. No Lab04, o dashboard ficou publicado no Streamlit Community Cloud e também abria com um comando, com uma versão estática como plano B. O mesmo padrão vale aqui.

**Objetivo**

Garantir que um comando regenera a análise e o dashboard a partir dos dados versionados, e publicar o dashboard.

**Definições adotadas**

- `python -m lab05` sem subcomando (ou `python -m lab05 tudo`) roda `validar`, `analisar` e o cálculo do impacto sobre `dados/brutos/`, sem Docker e sem refazer a coleta.
- O app (`python -m lab05 app`) só lê CSVs.
- Publicação no Streamlit Community Cloud a partir da `main`, como no Lab04; link no topo do README e do dashboard.
- Tempo da regeneração anotado no README.

**Interface congelada**

`python -m lab05` (tudo, sem coleta) e `python -m lab05 app`.

**Procedimento**

1. Implementar o comando que encadeia as etapas.
2. Rodar num clone limpo e anotar o tempo.
3. Publicar o app e conferir o link.
4. Atualizar o README.

**Saída esperada**

PR mesclado, dashboard publicado e README com o comando único e o link.

**Casos de borda**

- App publicado hiberna sem acesso: avisar no README, como no Lab04.
- Máquina sem Docker: o comando único não pode exigir Docker.

**Critérios de aceite**

- [ ] Um comando regenera a análise e o impacto.
- [ ] Dashboard publicado e link funcionando.
- [ ] README atualizado.
- [ ] CI verde.

Conteúdo das seções de impacto e conclusões (S03-07).
