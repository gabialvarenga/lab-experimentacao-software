\begin{abstract}
  DORA metrics (deployment frequency, lead time, change failure rate and time to restore) are the reference for software delivery performance, but public repositories do not record deployments or production failures. We mined them from the 300 most popular GitHub repositories that use GitHub Actions, over one year, using releases as a proxy for deployments and workflow runs as a proxy for failures. The median repository publishes 0.54 releases per week, has a lead time of about 11 days, a CI failure rate of 4.7\% (17.4\% when a failure is a release followed by a corrective release within 7 days) and recovers from a failed run in 2.6 hours. Deployment frequency correlates positively with the delivery-based failure rate (Spearman $\rho = 0.50$), partly by construction, and repository age is the characteristic most associated with performance. Changing the operational definitions moves 22\% to 30\% of the repositories to another category, and our corrective-release heuristic reached an F1 of 0.64, so per-repository values are estimates.
\end{abstract}

\begin{resumo}
  As métricas DORA (frequência de deploy, lead time, taxa de falha de mudanças e tempo de recuperação) são a referência para medir o desempenho de entrega de software, mas os repositórios públicos não registram deploys nem falhas em produção. Neste trabalho, mineramos as quatro métricas nos 300 repositórios mais populares do GitHub que usam GitHub Actions, em um ano, com releases como aproximação de deploys e execuções de \textit{workflow} como aproximação de falhas. O repositório mediano publica 0,54 releases por semana, tem lead time de cerca de 11 dias, taxa de falha de CI de 4,7\% (17,4\% quando a falha é uma release seguida de uma release corretiva em até 7 dias) e se recupera de uma execução com falha em 2,6 horas. A frequência de deploy tem correlação positiva com a taxa de falha por entrega (Spearman $\rho = 0{,}50$), em parte por construção, e a idade do repositório é a característica mais associada ao desempenho. Trocar as definições operacionais move 22\% a 30\% dos repositórios para outra categoria, e a nossa heurística de release corretiva alcançou F1 de 0,64, de modo que os valores por repositório são estimativas.
\end{resumo}
